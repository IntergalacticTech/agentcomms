One hub, many channels

Built-ins cover the common channels today. The adapter contract keeps the edge open for Discord, WhatsApp, Matrix, voice, fax, webhooks, hardware radios, or any other system that can produce events and accept replies.

✉

Email

AWS SES with DKIM, SPF, and DMARC. Custom domains in seconds. MIME parsing with quoted-reply stripping. Real threading via In-Reply-To and References headers.

⚡

SMS

AWS End User Messaging v2 with 10DLC. Inbound OTP extraction, outbound delivery receipts, per-number routing.

#

Slack

OAuth bridge into your workspace. DMs and @mentions route to the unified inbox; channel noise accessible via a native surface. Real signing verification.

✈

Telegram

BotFather-provisioned bot in seconds. Webhook-based ingest with per-channel token validation. DM and group @mention detection.

◉

Mobile Push

SNS Mobile Push to APNs and FCM. Per-agent device registration. Delivery receipts update message status automatically.

◆

Any Adapter

Third-party packages register through agentcomms.adapters. Use stable slugs like matrix, webhook, ham_radio, or alien-transmission.

Deploy it where your agents run

The default deployment target is your AWS account. The same Apache-2.0 codebase powers the hosted service path and the self-hosted path, so teams can inspect, fork, modify, and operate the hub directly.

Strict core, open edges

Core owns tenancy, authorization, normalized persistence, API keys, webhooks, and the unified inbox. Adapters own every provider-specific detail: OAuth, webhooks, signing, native threads, delivery receipts, and provider retries.

That split lets AgentComms stay small in the middle and broad at the edge. A new channel should not require a rewrite of the hub; it should require an adapter, tests, docs, and deployment wiring when the provider needs infrastructure.

  • Your data stays in your account
  • You pay AWS directly at AWS rates
  • Your adapter package can ship independently
  • The code is readable, auditable, and forkable

The unified inbox is the attention stream

Every direct message to your agent - email, SMS, Slack DM, Slack @mention, Telegram DM, push receipt, or third-party adapter event - is interleaved into one timeline. Ambient room traffic stays on native surfaces so the agent sees context only when it asks.

from agentcomms import Client client = Client(api_key="ak_live_...") # one-shot provision: agent gets email + SMS + Telegram + Slack result = client.agents.create( name="InvoiceBot", provision={ "email": {"local_part": "invoice"}, "sms": {"country": "US"}, "telegram": {"bot_token": "..."}, }, bridge={"slack": {"return_url": "https://..."}}, ) agent = client.agents(result["agent_id"]) # read the unified inbox — every channel, interleaved by time for msg in agent.messages.list(): print(f"[{msg.channel}] {msg.from_.address}: {msg.body_text}") # reply via auto-detected channel (email → email, E.164 → SMS, slack: → Slack) agent.messages.send(to="alice@example.com", body="Got it — processing.")

Adapters are public API

Built-in adapters live in this repository. External adapters can live anywhere, publish on their own cadence, and register through Python entry points when installed into the runtime.

# pyproject.toml in an external adapter package [project.entry-points."agentcomms.adapters"] matrix = "agentcomms_adapter_matrix.adapter:MatrixAdapter" # attach the adapter channel to an agent agent.channels.create( channel="matrix", mode="bridge", config={"homeserver": "https://matrix.example"}, )
